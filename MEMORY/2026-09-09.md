## Notification module — design phase
- Brainstormed v1 notification design (bell icon). Doc pasted by user was directionally good (event pipeline, taxonomy) but overbuilt; stripped it down.
- Key calls: polling only (45–60s unread-count; no WebSocket/SSE — zero WS infra today, JWT+STOMP auth is fiddly, subdomain-per-firm origin checks); SYSTEM|ALERT|BROADCAST taxonomy (TRANSACTIONAL stays in EmailService — it's a request-response flow, not a notification); one table in v1 (no delivery/preference/template tables — each has a defined Phase-2 trigger); code-level renderer not DB templates; priority field dropped.
- V1 producers: case/matter assigned (SYSTEM → advocate), invoice status change (SYSTEM → firm admins). Hearing/appeal alerts + broadcast + email channel deferred to Phase 2.
- Entities use UUID (AuditableEntity), not Long as pasted doc sketched.
- Design presented, awaiting user approval → then spec doc + implementation plan.
