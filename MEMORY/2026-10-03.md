## Document upload rebuilt: one call, no confirm (full replacement)

- Requirement: remove the 3-step flow — the client uploads the file and the document is `ACTIVE`
  immediately, no confirm. User chose **full replacement** (delete ticket/confirm/sweeper/PENDING).
- **Why the design had to change:** the old flow uploaded bytes straight to storage, so only the
  browser knew when the upload finished — that is exactly why `confirm` existed. To finish the upload
  on its own the API has to receive the file, so upload is now **one `multipart/form-data` POST** to
  `POST /api/v1/firm/documents` (parts: `file` + `matterNumber`/`projectCode` + optional
  `courtCaseRef`). Trade-off: bytes now pass through the app (fine for the 50 MiB cap).
- **Code:** `StorageService.presignUpload` → `put(key, InputStream, size, type)`; `MinioStorageService`
  uses `client.putObject`. `DocumentService.initiateUpload`+`confirmUpload` → `upload(...)`; the
  controller method is multipart. Deleted `UploadTicket`, `InitiateUploadRequest`,
  `ConfirmUploadRequest`, `UploadTicketResponse`, `PendingUploadSweeper`; removed `PENDING_UPLOAD`
  from `DocumentStatus`, `uploadExpiresAt` from `Document`, and the sweeper query from
  `DocumentRepository`. Added `spring.servlet.multipart` limits (60 MB transport ceiling vs the
  50 MB STORAGE policy).
- **Tests:** rewrote `DocumentServiceImplTest` (upload authorization/validation/keys/storage) and
  `DocumentQaTest` (multipart requests via `MockMultipartFile`). `FakeStorageService` now implements
  `put` and consumes the stream, so size/signature checks stay real. **616 tests green.**
- **Legacy data:** the dev DB held abandoned `PENDING_UPLOAD` rows (14/15) that the enum no longer
  knows — deleted them (same thing the sweeper would have done). documents table now empty.
- Note: `FakeStorageService` is a singleton bean shared across a test class, so assertions must
  compare counts, not assume an empty store.
- The running app is still on the OLD build — it must be restarted to expose the new endpoint.
