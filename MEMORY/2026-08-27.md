## Two-Tier Permission Ceiling Overhaul

- **Problem**: When a new firm was created, `cloneSystemRolesForFirm()` copied ALL RolePermission entries from system roles to firm roles, making every permission auto-enabled. FIRM_ADMIN started with full access instead of zero. Also caused "Permission HOME scope TENANT not allowed for FIRM_ADMIN" errors.
- **Solution**: Two-tier ceiling architecture:
  - **FIRM_ADMIN role**: ceiling = parent system role's permissions (SUPER_ADMIN controls via `/api/v1/admin/roles/permissions`)
  - **Other firm roles** (ADVOCATE, PARALEGAL, custom): ceiling = firm FIRM_ADMIN's enabled permissions (FIRM_ADMIN controls)
  - New firm roles start with ZERO permissions enabled
- **Files changed**:
  - `FirmServiceImpl.cloneSystemRolesForFirm()` — removed RolePermission copying loop; firm roles now start empty
  - `FirmRoleServiceImpl.getRolePermissions()` — two-tier ceiling via `computeCeiling()` helper
  - `FirmRoleServiceImpl.updateRolePermissions()` — two-tier ceiling check
  - Added `computeCeiling()`, `isFirmAdminRole()`, `findFirmAdminRole()` helpers
  - Updated `FirmRoleServiceImplTest` — unit tests for both ceiling tiers
  - Updated `FirmAdminE2ETest` — E2E tests for full two-tier flow
  - Updated `RolePermissionE2ETest` — E2E tests for cross-firm isolation with new architecture
- **Test results**: 230 pass, 0 failures
- **Key insight**: Enabling FIRM_ADMIN permissions invalidates its own JWT (permVersion bump); tests must re-fetch user from DB and regenerate token after modifying FIRM_ADMIN

## ModuleMapper MyBatis fix
- **Problem**: `ModuleMapper.findAllModules` threw `Invalid bound statement (not found)` in tests
- **Root cause**: Test `application.yml` was missing `mybatis` config section entirely (mapper-locations, type-aliases-package, type-handlers-package). Without it, MyBatis never loaded the XML mappers. When XML was finally found, UUID type handler was missing.
- **Fix**: Added full `mybatis` config block to `src/test/resources/application.yml` (mapper-locations, type-aliases-package, type-handlers-package, configuration)
