# 2026-09-25

## Firm update endpoint (reported bug: "Admin password is required" when editing a firm)

- **Diagnosis, not a validation bug:** `Admin password is required` has exactly one source —
  `CreateFirmRequest.adminPassword` (`@NotBlank`) — and the only endpoint binding that DTO is
  `POST /api/v1/super-admin/firms`. So the console's Edit dialog was POSTing to **create**.
  There was no firm-update endpoint at all (`FirmAdminController` had only suspend/activate/
  extend-trial/convert-to-permanent). Even with a password supplied, the edit would have died on
  `Firm code 'X' already exists` — the create endpoint can never serve as update.
- **Fix:** new `PUT /api/v1/super-admin/firms/{firmId}` + `UpdateFirmRequest`; firm details and the
  firm admin's fullName/email/mobile are updatable, no password in the payload.
- **Decision — immutables are rejected, not ignored.** `lawFirmCode`, `adminUsername` and
  `adminPassword` are accepted in the DTO *only* so the create body can be replayed unchanged
  (the FE reuses one dialog). An identical value passes; a *different* value is a 400 with a
  pointer at the reset-password endpoint. Silently accepting a password change is exactly the
  `AUTH-14` failure mode (a dropped credential looks like a successful save).
- **Null/blank handling:** omitted field = leave as is; explicit `""` on a nullable text column
  clears it. A partial edit form can no longer wipe the columns it never sent.
- **Which admin:** the firm's FIRM_ADMIN. Several users can hold FIRM_ADMIN (employee promoted to
  it), so the **oldest** by `createdAt` is treated as primary — deterministic across repeated
  edits without changing the shared `findFirmAdminsByFirmId` ordering. Admin details sent for a
  firm with no FIRM_ADMIN row fail loudly instead of vanishing.
- **Uniqueness:** admin email/mobile are checked per firm and only when the value actually changes
  (otherwise an unchanged email collides with its own row).
- Audit: `FIRM_UPDATED` on the firm, with the admin id as the actor when present.
- Tests: `FirmServiceUpdateTest` (15, Mockito) + `SuperAdminQaTest` SA-04b/SA-04c (update without a
  password; code/username/password rejected; firm admin denied). **488 green** (was 471).
- Also added an `Update Firm (SA)` request to `docs/postman/RBAC-V3.postman_collection.json`.
- **Owed on the frontend** (not in this repo): point Edit at `PUT /api/v1/super-admin/firms/{firmId}`.
  Same envelope + body shape as create, minus the password — the old POST /firms call cannot work.
