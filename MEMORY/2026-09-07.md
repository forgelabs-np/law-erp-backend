## RBAC state-of-the-world doc
- User asked: how are roles/permissions assigned today (SA vs Firm Admin), and noted SA "can't give permissions to employees" — wanted SA → Firm Admin → employees chain
- Audited the whole RBAC surface before answering: entities, seeding matrix, FirmServiceImpl cloning, PermissionEvaluator, RoleController/FirmRoleController/SuperAdminController, bulk-role-change
- Key findings:
  - Delegation design already exists (two-tier ceiling: FIRM_ADMIN clone capped by system template; other firm roles capped by firm FIRM_ADMIN's perms)
  - Gap 1: system role templates are immutable (validateNotSystemRole + isSystem guard) → SA ceiling control is static seed data, "SA sets FIRM_ADMIN ceiling" comment is aspirational
  - Gap 2: SA can't grant employees beyond their parent template via normal path — only per-firm/per-role override endpoint (Sep 2) escapes the ceiling
  - Gap 3: SA has no GET endpoint to list a firm's roles → override flow undiscoverable
  - UserRole join table is legacy (written once at firm creation, not used for checks since PermissionEvaluator switched to User.role FK)
- Wrote `docs/rbac-roles-and-permissions.md` — current state, endpoint/guard tables, seed matrix, achievements timeline, gaps, follow-ups
