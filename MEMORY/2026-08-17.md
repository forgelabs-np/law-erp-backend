# Memory — 2026-08-17

## What we built: `scraper` module (Nepal Supreme Court hearing tracking)

New Spring Boot module `com.lawfirm.erp.modules.scraper` — scrapes supremecourt.gov.np
cause lists, matches them against our client cases, and notifies on new hearings.

### Why plain HTTP, not Selenium
The site is server-rendered PHP forms returning full HTML on POST — Selenium would add a
browser for no benefit. Used `java.net.http.HttpClient` + jsoup (added to pom) behind a
`CourtSiteClient` interface so a browser-backed impl can be swapped in later if the site
ever gates on JS. The user's own spec (httpx) was plain HTTP too.

### Verified live site mechanics (today)
- GET the endpoint first → server issues PHPSESSID + `court_session` + F5 `TS...` cookie.
  `court_session` binds the USER_AGENT → must send a consistent browser-like UA.
- POST → **302** with a flash in `court_session` (e.g. "causelist not published") → follow
  Location with GET. Java HttpClient does NOT follow 302 on POST → manual follow in
  `HttpCourtSiteClient`.
- **Daily** form: `todays_date` (Arabic BS) + `pesi_date` (Devanagari BS) + `submit=खोज्नु होस्`.
  Daily pages for past dates return "Causelist is not available" — today's isn't published
  until later morning. Daily = 10-col rows, per-judge इजलाश sections, separate वादी/प्रतिवादी,
  has आदेश फैसलाको किसिम (outcome) column.
- **Weekly** form: `pesi_bar=all` (day-of-week select, NOT pesi_date) + submit. Returns the
  whole Sun–Fri week (~1.7 MB), grouped by `पेशी मिति :<date>`, flat tables, single
  `पक्ष || विपक्ष` column split on `||`/`‖`, **no** outcome column.
- Case numbers come in two forms per cell: `०८१-C४-३८२७` (court-visible) and
  `(३९-०८१-३२०३०)` (court-scoped internal id). Both extracted + normalized to Arabic.
- Court ids: 39 = Kathmandu, 63 = Gulmi; consistent across all 4 tab endpoints.

### BS ↔ AD conversion
`NepaliDateUtil` — month-length table for BS 2000–2090 (91 years, extracted from the
`nepali-date-converter` npm package 3.4.0), epoch BS 2000-01-01 = AD 1943-04-13,
AD = 1943-04-13 + daysPassed. Verified: 2081-01-01 → 2024-04-13, 2083-05-01 → 2026-08-17.
`DevanagariConverter` for ०-९ ↔ 0-9.

### Module layout
- `entity/`: Court (courtId PK, standalone — NOT auditable, else double-@Id), ClientCase
  (courtId + caseNoInternal, ACTIVE drives the court list), DailyHearing / WeeklyHearing
  (unique key courtId+caseNoInternal+hearingDateBs → idempotent upsert), HearingMatch.
- `parser/`: DailyTableParser (10-col, skips summary table, judge from इजलाश heading),
  WeeklyTableParser (9-col, date headers, party split), CaseNumberExtractor.
- `client/`: CourtSiteClient interface + HttpCourtSiteClient (session, 302 follow, rate limit).
- `service/`: HearingIngestionService (upsert), HearingMatchingService (join client_cases ×
  hearings on courtId+caseNoInternal, dedupe, at-least-once notify), NotificationDispatcher
  interface + LogNotificationDispatcher stub, ScraperService (orchestrator: active courts →
  concurrent fan-out on bounded executor → ingest → match+notify; alerts on failure/0 rows),
  ScraperScheduler (@Scheduled 10:05 weekdays / 10:15 Mon, `scraper.daily-cron` etc.).
- `controller/`: GET `/api/v1/cases/{caseNo}/hearing-status` (DB only), POST
  `/api/v1/scraper/admin/scrape?courtId=&date=` (FIRM_ADMIN).
- `config/`: ScraperProperties (`scraper.*`), SchedulingConfig (`@EnableScheduling` — this
  ALSO activated the previously-dormant AppealDeadlineEngine cron; documented in its javadoc).

### Gotchas for tomorrow
- `-Dtest='scraper.*'` doesn't match by package — use class names or run the whole suite.
- Windows classpath separator is `;` not `:` when compiling standalone mains.
- Git Bash `grep -E "[ \t]+$"` is unreliable (`\t` not interpreted) — use `[[:blank:]]+$`.
- Node on Git Bash resolves `/tmp` to `G:\tmp` — copy files into the project for node scripts.
- The daily feed for a given date is often "not published" in the morning — 0 rows is
  expected, not an error; the orchestrator logs it as an alert.

### Late correction — the REAL daily structure (user supplied the actual response)
The real daily page's judge sections are NOT `h3` headings (as first assumed) — they are
**plain header tables** with `<td><b> इजलाश N</b></td>` + `<td class="judge"><b> माननीय
जिल्ला न्यायाधीश श्री …</b></td>`, followed by a `record_display` detail table
(10 cols). DailyTableParser rewritten to extract the judge NAME from `td.judge` and the
page date from the "मिति <date> को दैनिक पेशि सुची" title. Verified against the real
660 KB response: **672 rows = exactly the site's own जम्मा total**, 30 judges, 72 rows
with outcomes (स्थगित/आदेश/फैसला). Fixture `daily_kathmandu_39.html` is now the real file.
