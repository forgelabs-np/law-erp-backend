## RBAC delegation-chain design (in progress)
- User goal: SA shapes Firm Admin ceiling → Firm Admin customizes employee roles per firm → later custom roles. Picked up from `docs/rbac-roles-and-permissions.md` gaps.
- Decisions (user-confirmed):
  - **Role-level only for v1** — no per-user permission grants/denies. "John needs edit" → firm admin creates a custom firm role, reassigns John. (Why: avoids both role-explosion and user-level eval complexity; firm-scoped clones already give per-firm customization)
  - **SA template edits auto-sync to all firms + cascade narrowing** (recompute employee ceilings, strip over-ceiling perms). (Why: strongest SA control; permissionVersion machinery already handles session invalidation)
  - **"Custom permissions" = custom ROLES** composed from the system permission catalog, NOT firm-invented codes. (Why: a firm-invented code has no backend check → dead grant)
- External design review (user pasted) analyzed:
  - Recommends **diff-based sync (Option B)** over hard sync — propagate only SA's added/removed delta; preserve untouched firm customizations. Notes hard sync contradicts the codebase's own additive-seeding principle.
  - Flags **seeder freeze column** (sa-edited templates must not be re-seeded from matrix on boot).
  - Recommends async sync job, cascade surfaced to actor, chain-validation errors naming offending templates, audit correlation ID, phased plan 0–5.

Pushback: async job premature (no job infra exists; per-firm tx batches fine at current scale — build batch-shaped so @Async is a small later change; flip at O(1000) firms).
