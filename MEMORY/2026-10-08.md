## Firm brand/logo — finished yesterday's build + contract

The 2026-10-07 brand/profile work compiled red and could not be tested. Completed it; suite is
**659 green** (was unverified at 627 before the brand work landed).

- **Build was red from the brand work itself, not `SystemConfigService`** (that file is fine: it has
  `@Slf4j` and `StorageProperties` has real Lombok getters). Actual breaks:
  - 5 missing `FirmConstants` summaries the controller referenced (`GET_FIRM_THEME_SUMMARY`,
    `UPDATE_FIRM_THEME_SUMMARY`, `GET_FIRM_LOGO_SUMMARY`, `UPLOAD_FIRM_LOGO_SUMMARY`,
    `SET_FIRM_LOGO_ALLOWED_SUMMARY`) — added.
  - `MinioStorageService.client()` used `ObjectProvider.getIfAvailable().orElseThrow(...)`; that
    overload returns `T`, not `Optional<T>` — replaced with a null check.
  - `FirmStorageService` called `put(key, stream, contentType)` but the interface needs `sizeBytes` —
    passed `file.getSize()`.
  - `FakeStorageService` was missing the new `presignFirmLogo` override — added.
  - `SetLogoUploadRequest` + `@RequestPart SetLogoUploadRequest` could never bind a file part
    (a file part has no HttpMessageConverter to a DTO) — controller now takes `@RequestPart("file")
    MultipartFile` and the dead DTO was deleted.

- **`logoAllowed` default flipped to off** as asked: entity default `false`, migration
  `DEFAULT false` (was `true`).

- **Logo storage bugs fixed** (feature would not have worked end-to-end):
  - `presignFirmLogo(UUID)` hardcoded `logo.png`, so any jpg/webp logo produced a dead link — it now
    takes the real object key (`presignFirmLogo(String)`).
  - It also forced `response-content-disposition: attachment`, which makes a browser download the
    logo instead of rendering it — dropped (inline).
  - `deleteFirmLogo` rebuilt the key from the full presigned URL, query string included, so the prior
    object was never deleted — the query string is now stripped.
  - `setMyFirmTheme` captured the "old" hex *after* mutating the entity, so the audit line was
    `x -> x` — capture moved before the mutation.

- **Validation now throws `BusinessRuleException` (400) not `StorageOperationException`.** The
  document module already does this; `GlobalExceptionHandler.handleStorageOperation` replaces the
  message with "Document storage is temporarily unavailable", so logo type/size errors were reaching
  the FE as a masked 502. Type/size/empty are 400 with the real message; 502 is reserved for genuine
  store failures. The FE guide's error table was corrected to match.

- **`isPersonalColor` was never actually implemented** — `FirmProfileResponse` and
  `MeResponse.FirmInfo` only had it in the memory notes. Now:
  - `BrandColorValidator.hasPersonalColors(primary, secondary)` = true when *either* hex is set.
  - `FirmProfileResponse.isPersonalColor` is a boolean (always present).
  - `MeResponse.firm.isPersonalColor` is a `Boolean` with `@JsonInclude(NON_NULL)`, set `true` only
    when a color is set and **omitted entirely when not** — the user's ask ("send the flag too, else
    don't"). `me.firm` also gained `logoAllowed` / `brandPrimaryHex` / `brandSecondaryHex`, and the
    top-level `logoAllowed`/`logoUrl` (previously always false/null) are now populated from the firm.

- **Docs** — `docs/firm-brand-profile-guide.md` updated: 400 for logo type/size, hex fields null when
  unset, and the "isPersonalColor omitted when not personal" contract.

- **Tests added** — `BrandColorValidatorTest`, `FirmStorageServiceTest` (key/extension + delete-key
  recovery), `FirmBrandServiceTest` (theme normalization, partial update, toggle, upload allowed /

## Hibernate query performance pass (audited all 48 repositories + entity associations)

Only 4 repositories used `JOIN FETCH` and none used `@EntityGraph`, which is what the N+1s grew from.
**671 tests green.**

Tier 1 — `spring.jpa.properties.hibernate.default_batch_fetch_size: 100` in `application.yml`. Turns
any remaining lazy load into batched `IN (...)` queries; no result change. (Note: test resources have
their own `application.yml`, so this is not exercised by the suite.)

Tier 2 — six fetch fixes: `@EntityGraph` on `findAllWithRoleAndFirmPaged` (role+firm),
`findAllFirmAdmins`/`findFirmAdminsByFirmId` (firm), `CustomerProfileRepository.findMatches` (user);
and batched queries in `ClientPortalServiceImpl.listMyProjects` and `ProjectDashboardServiceImpl`
(the latter was N+1 across three levels: per-project counts, per-project renewals, per-renewal
instances, plus a type lookup per renewal).

Tier 3 — unbounded loads: `UserManagementServiceImpl.listUsers`/`searchUsers` filtered, sorted and
paged in Java over the whole user set (the whole table for a Super Admin) — replaced with a new
`UserRepository.searchPaged` (optional firm/userType/roleId/isActive/search + `Pageable`) and the
`paginateList` helper deleted; `getUserProfile` loaded every audit row for the month to read
`getTotalElements()` — now `AuditLogRepository.countByFirmAndUser`; `GlobalDashboardServiceImpl`
loaded every `Matter` entity to compute counts — now `countByFirmId`/`count()` plus a leaf-id
projection (`findLeafCourtCaseIds`/`...ByFirmId`), with the stale formula preserved exactly
(`(total - leafIds.size()) + leavesWithoutRecentPeshi`); `HearingMatchingService` did
`clientCaseRepository.findAll()` then filtered in Java — now `findByActiveTrueAndCaseStatus`.

**Deliberately not changed:** `FirmServiceImpl.getAllFirms()` is unpaginated, but making it paged would
change the response shape the FE consumes (contract break), and `Firm` has no associations so it is
not N+1. `User.role` stays `fetch = EAGER` — it is joined, not N+1, and flipping it to LAZY risks
`LazyInitializationException` in `getAuthorities()`/`JwtUtil`/`PermissionEvaluator` (all run outside a
transaction). Also left: `ProjectMapper.resolveUserName`/`toMemberResponse` issue a `findById` per
row, and `ClientPortalServiceImpl.listMyRenewals` still loops instances per renewal.

**Verification:** `FetchGraphQueryTest` (new, H2-backed) asserts the associations come back
*initialized* from the real queries — confirmed non-vacuous by temporarily dropping one `@EntityGraph`
and watching it fail. New `ProjectDashboardServiceImplTest`/`ClientPortalServiceImplTest` assert the
batched call counts and that the old per-row methods are never called.
