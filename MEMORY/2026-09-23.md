# 2026-09-23

## QA fix batch — six reported bugs

Six bugs off `docs/ui-test-checklist.md` plus the client-portal login report, all fixed in one
sitting. Full per-bug write-up (symptom → root cause → change → manual steps) is in `fixes.md` at
the repo root. **461 tests green** (was 423 recorded), `BUILD SUCCESS`.

Run (the shell's default `JAVA_HOME` is JDK 17 and cannot build this module):
`JAVA_HOME=/c/Users/Dev/.jdks/ms-21.0.12 ./mvnw -o test`

1. **Client portal could not log in (1.12).** `login` resolved a client by *mobile number only*
   while the portal's single, username-labelled field is what clients type. Added
   `findClientAccount()` (mobile → then username) and added the mobile arm to `forgotPassword`.
   Regression test `AUTH-09b` creates a client and signs in with both identifiers.
2. **Reset / change password (1.8, 1.9).** Three defects at once: (a) the admin reset endpoint
   required `ApiRequest<ResetPasswordRequest>` with a mandatory password, but the console's reset is
   a confirmation dialog that posts **no body** → 400 before the controller; (b) the reset accepted
   `aaaaaa` because client creation allowed 6 characters and the resets 8; (c) no self-service
   "change my own password" existed. Fixes: a new `RequestBodyBinder` (envelope or bare body,
   body optional), a new `PasswordPolicy` (8–50) used by both resets, client creation and the new
   endpoint, a generated temporary password returned once when the admin supplies none, and a new
   `POST /api/v1/me/change-password` that proves the current password and revokes other sessions.
3. **`isTrial` (2.8).** Added `isTrial` / `trialDays` / `trialExpiresAt` to `FirmAdminResponse` and
   `FirmProfileResponse`; populated in the two service builders. `FirmMapper`'s duplicate (and
   uncalled) builders were left alone — flagged for deletion in `fixes.md`.
4. **Bulk deactivate (4.10).** Same binding bug as 2.1 — the screen posts `{"userIds": […]}` bare.
   Both bulk endpoints now bind through `RequestBodyBinder`, and an empty selection is rejected in
   the service (the envelope's `@Valid` never covered these paths).
5. **Assignment e-mail (5.7).** `CASE_ASSIGNED` *was* published, but e-mail defaulted on for ALERT
   types only, so a SYSTEM assignment only produced an in-app row. `NotificationType` now declares
   `emailsByDefault` per type; `CASE_ASSIGNED` is the one SYSTEM type that declares true and stays
   overridable.
6. **Unassigned employee saw every matter.** `GET /firm/matters` only narrowed for clients; every
   other non-admin fell through to the firm-wide query (the dashboard already scoped by assignment).
   Added `ReadScopeGuard.isAssignmentScope()`, routed the matter and stale-matter lists through a
   new `assignedMatters()` (empty page when the caller has none) and a
   `MatterRepository.findByFiltersAndIdIn(...)` that keeps all existing filters.

### Gotchas learned

- **No converter is registered for `JsonNode` request bodies** in this app's web layer, so binding
  `@RequestBody JsonNode body` fails with `Type definition error: [simple type, class
  com.fasterxml.jackson.databind.JsonNode]` and surfaces as the 400 the whole batch was meant to
  fix. Take the body as `String` and parse it with the `ObjectMapper` (`RequestBodyBinder` does).
- `./mvnw` picks up `JAVA_HOME=…ms-17.0.20` from the environment; pass the JDK 21 path explicitly.
- Test counts: full suite 461; the QA suites are 63 (`AuthSecurityQaTest` 16, `SuperAdminQaTest` 16,
  `FirmRoleMatrixQaTest` 12, `CaseManagementQaTest` 11, `ProjectManagementQaTest` 8).
