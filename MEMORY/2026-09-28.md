# 2026-09-28

## Phase 1 document store — MinIO-backed, case-or-project, per-firm quota — 613 tests green

### What was built

- **Generic storage seam** `common/storage/`: `StorageService` (interface), `MinioStorageService`
  (the **only** `io.minio` importer, client resolved lazily via `ObjectProvider<MinioClient>` so the
  app and the whole test suite boot with no storage configured), `StorageProperties`
  (`storage.minio.*`), `StorageConfig` (`@ConditionalOnProperty` on `endpoint`), `StorageBootstrap`
  (creates the bucket, logs rather than fails), `UploadTicket`, `StoredObject`.
- **No feature module touches MinIO.** `DocumentServiceImpl` depends on `StorageService`, which is why
  125 of the suite's tests run in-memory with no container, no network and no credentials.
- **Quota** is its own table, not a firm config key: `FirmStorageUsage` (`firm_id` unique, `used_bytes`,
  `quota_bytes`) + `StorageQuotaService` (`0 = UNLIMITED`, `canFit`, `reserve`, `release`, `setQuota`,
  `findForUpdate` with `PESSIMISTIC_WRITE`). Allocation is **Super-Admin-only**
  (`PUT/GET /api/v1/super-admin/firms/{firmId}/storage-quota|storage-usage`) *on purpose* — in firm
  settings a firm admin could raise their own limit.
- **Document module** `modules/document/`: entity (own `Long` PK + `uuid`; does **not** extend
  `AuditableEntity`, whose PK is a UUID — follows the `ProjectMember` pattern), 9 firm endpoints,
  2 client-portal endpoints, `DocumentScopeGuard`, `DocumentTypePolicy`, `DocumentStoragePath`,
  `PendingUploadSweeper`.
- **Documents bind to exactly one of a case or a project** (`matter_id` XOR `project_id`), with an
  optional `court_case_id` tag mirroring `MatterTimelineEvent`. Enforced by a DB check constraint
  (`V2026_09_28__document_store_constraints.sql`) as well as in the service.

### Key decisions

- **Presigned POST policy, not presigned PUT.** A PUT URL is a bearer credential for one key and
  *cannot* cap the size written to it (MinIO would take a single PUT up to 5 GB), which would make the
  50 MB cap advisory. The POST policy signs `content-length-range`, `eq key` and `eq Content-Type`, so
  storage enforces all three. Bytes never pass through the API.
- **Confirm is where trust is withdrawn.** Everything declared at ticket time is re-verified against
  what landed: `stat` size equals declared size, real size under the cap, and the leading 4 KiB match
  the declared type's **file signature**. Every rejection **deletes the object** before failing, so a
  failed confirm leaves no orphan. A renamed executable with a spoofed header dies here.
- **Downloads are gated on `:VIEW`, not `:DOWNLOAD`.** The seeded `READ_ONLY` (paralegal) and `OWN`
  (client) roles hold only `ACCESS + VIEW`; gating on `:DOWNLOAD` would lock both out of reading any
  file — the same shape as QA finding F-14. `:DOWNLOAD` stays in the catalogue, unused.
- **Sharing is one flag, not a grant table.** Private by default; `DOCUMENT_MANAGEMENT:SHARE` promotes
  to `SHARED`, which is the only thing the client portal query looks at.
- **Archive releases the quota but keeps the bytes.** Legal documents are never destroyed by a DELETE.
- **Storage path is readable on purpose:** `firms/{firmId}/cases/{matterNumber}/{uuid}/{filename}`
  (or `.../projects/{projectCode}/...`) — traceable back to the case from the bucket alone.

### Three real bugs found and fixed in shared, previously-green code

1. **`AuditSpelHelper.evaluate` never bound `#result`.** It set the result only as the SpEL *root*
   object, while every annotation uses `#result.x` — so each expression threw `VARIABLE_NOT_FOUND`,
   was caught, and returned null.
2. **`AuditAspect.getCurrentUser()` only read the SecurityContext principal**, which is an
   `AuthenticatedDetail` and never matched `instanceof AuthenticatedUser`. Now injects
   `CurrentUserResolver` and reads the request attribute first, matching `AuditServiceImpl`.
3. **Consequence of 1 + 2: no `@Audit`-annotated method anywhere in the app had ever written an audit
   row.** Fixed centrally, so every module benefits — not just documents.

### Other issues found and fixed while testing

- `etag` (`VARCHAR(64)`) was written straight from client-supplied `ConfirmUploadRequest.etag`; a long
  value blew the insert (`Value too long for column "ETAG"`). `normalizeEtag()` strips quotes and drops
  a value that is empty or over 64 chars rather than truncating it (a partial etag would mislead).
- `MatterScopeGuard.requireVisible(matterId, firmId, what)` checked **only** `MatterParty` rows and
  ignored `Matter.clientUserId` — it refused every matter bound through the column, which is how the
  client portal binds matters today. Now resolves the column first, then the party fallback.
- `DocumentScopeGuard.requireVisible(Project)` demanded project membership for staff. Changed to
  `requireProjectReadable(Project)`: staff pass (the listing query is already narrowed to their
  memberships, so a non-member gets an empty page) and clients must own it. Uploads still require
  membership.
- **Two disagreeing whitelists.** `DocumentTypePolicy.ALLOWED_TYPES` (content type) and the app-wide
  `AllowedExtensions` enum (filename) did not match: `.tiff`/`.zip` were whitelisted by type but
  refused by extension, and `.gif`/`.svg` passed the extension gate then failed the type gate with a
  message about "unsupported content type". `DocumentTypePolicy` now **derives** its accepted
  extensions from `ALLOWED_TYPES` (+ the `jpeg` alias), so the gates cannot drift apart and the error
  lists exactly the set that works. Three tests pin the agreement both ways.
- `pom.xml`: minio 8.6.0 pulls okhttp 5.x, whose `okhttp` artifact is an empty KMP metadata jar — the
  JVM classes need `com.squareup.okhttp3:okhttp-jvm:5.1.0` declared explicitly.

### Audit-log integration

`UPLOADED`, `DOWNLOADED`, `SHARED`, `DELETED` all already existed on `AuditEntity.DOCUMENT` /
`AuditAction`, so no new enums were needed — only `TimelineEventType.DOCUMENT_UPLOADED` (case documents
only; projects have no timeline). `audit_logs.entity_id` is a **UUID**, which is why `Document` carries
a `uuid` column alongside its numeric PK. Audit summaries carry the filename and deliberately **never**
the presigned URL: the tests assert the summary never contains `http`.

### Infrastructure

`application.yml` + `-dev.yml` (`localhost:9000`) + `-prod.yml` (`${MINIO_*}`), `.env.example`
(`MINIO_*`, `DEFAULT_STORAGE_QUOTA_BYTES`), and a root `docker-compose.yml` (MinIO + console :9001,
named volume, healthcheck). Defaults: 50 MiB max file, 30 min upload window, 15 min download link,
5 GiB default allocation on a firm's first write.
