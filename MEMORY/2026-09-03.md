# 2026-09-03

## UserType Expansion: FIRM added

- Added `FIRM` enum value to `UserType` between `SUPER_ADMIN` and `FIRM_USER`
- `FIRM` = firm owner/admin, `FIRM_USER` = employees (lawyers, paralegals, clerks)
- Updated `User.java` with `isFirmAdmin()` helper
- Updated `AuthenticatedUser.java` with `isFirmAdmin()` method
- `FirmServiceImpl.createFirm()` now sets admin user type to `FIRM` (was `FIRM_USER`)
- `FirmAdminServiceImpl.validateIsFirmAdmin()` now checks `UserType.FIRM`
- `DataInitializer` seeds `FIRM_ADMIN` role with `applicableTo(UserType.FIRM)`
- `GlobalDashboardServiceImpl` active user count includes `FIRM` users
- Created Flyway migration `V2026_09_03__add_firm_user_type.sql`:
  - Drops/recreates `users_user_type_check` constraint with `'FIRM'`
  - Backfills existing firm admin users from `FIRM_USER` → `FIRM`
  - Updates system `FIRM_ADMIN` role `applicable_to` → `'FIRM'`
- Fixed `GlobalDashboardServiceTest` — added mock for `countByUserType(FIRM)`

## Audit Log Filtering by UserType

- `AuditServiceImpl.toUserTypeChar()` maps `FIRM` → `'A'` (new char)
- `AuditLog.userType` char mapping: `S`=SUPER_ADMIN, `A`=FIRM, `F`=FIRM_USER, `C`=CLIENT
- `AuditLogRepository.findAllWithFilters()` now accepts `action`, `userType`, `userId` at DB level (was in-memory filtering)
- Removed unused `findByActionGlobal()` method
- `SuperAdminAuditController` `GET /audit` now accepts `userType` + `userId` params
- Added `resolveUserTypeChar()` — accepts both char (`S`,`A`,`F`,`C`) and enum names (`SUPER_ADMIN`,`FIRM`,etc.)
