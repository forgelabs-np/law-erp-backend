### Confirmed faults found + fixed (all with regression tests)
1. **JwtAuthFilter never populated `AuthenticatedUser.roles`** (left null) -> DashboardService `isAdmin` check always false -> FIRM_ADMIN got an assigned-only (usually empty) dashboard. Fixed: set roles from roleCode claim. Test: JwtAuthFilterTest.
2. **DashboardService stale inconsistency**: matters with no last-hearing date appeared in `staleCases` but had `stale:false`. Fixed: `stale = lastDate == null || daysSince > 90`. Test: DashboardServiceTest.
3. **N+1**: buildPositioning queried events per matter. Fixed: batch `findByCourtCaseIdInAndFirmIdOrderBySequenceNoAsc` + group in memory.
4. **GlobalDashboardService.buildScraperStats loaded the whole daily_hearings table** (14k+ rows) for max date + swallowed a broad Exception. Fixed: `DailyHearingRepository.findMaxScrapedDate()` query.
5. **CaseAssignmentService.assign allowed CLIENT users**. Fixed: require UserType.FIRM_USER. Test added.
6. **DashboardService buildAdvocateMap NPE**: `Map.of().get(null)` when a matter had no court case -> whole dashboard crashed. Fixed: null-guard the key.
7. **DashboardService buildPositioning NPE**: `.daysSinceLastHearing(daysSince>=0?daysSince:null)` unboxed null into int builder param -> dashboard crashed for any matter with no hearings. Fixed: changed DTO field to `Integer`.
