## Auth & SuperAdmin Refactoring

- Created `auth/mapper/AuthMapper.java` — extracts all LoginResponse building from service layer (success, MFA setup, MFA required, password change required). Why: services were cluttered with response construction logic that belongs in a mapper.
- Created `auth/service/AuthService.java` as interface, renamed existing to `AuthServiceImpl.java`. Why: user wanted all services to follow interface + impl pattern consistently.
- Created `common/constant/AuthConstants.java` — centralized Swagger summary/description strings for all auth endpoints. Why: inline strings in controllers are messy and inconsistent.
- Updated `AuthController.java` to use constants and reference the interface. Removed all commented-out dead code (registration endpoints that were disabled).
- Updated `AuthServiceImpl.java` — uses AuthMapper for response building, extracted helper methods (`validateAccountStatus`, `handleFailedLogin`, `handleMfaFlow`) for cleaner code.
- Created `superadmin/service/SuperAdminService.java` as interface, created `SuperAdminServiceImpl.java` with same pattern.
- Created `common/constant/SuperAdminConstants.java` for Swagger strings.
- Updated `SuperAdminController.java` to use constants.
- Updated `SuperAdminServiceTest.java` — added `@Mock AuthMapper` and stubs for all mapper method calls. The old test assumed the service built responses directly.

- Why constants per-module instead of one big constants file: keeps constants close to their controllers, easier to find and maintain.
