## Auth/RBAC hardening pass (unlogged)

Files touched: `TotpUtil`, `JwtUtil`, `AuthServiceImpl`, `SuperAdminServiceImpl`, `SecurityConfig`,
`UserManagementController`, `RefreshTokenRepository`, `GlobalExceptionHandler`, `PermissionEvaluator`,
`AuthenticatedUser`, `HeaderWrapper`, `ConfigEncryptionUtil` + new `EncryptedStringConverter`,
`User`, `UserRepository`, `SystemConfigService`/`ConfigKeyRegistry`, `application-dev.yml`,
scraper/case-management/portal controllers, and new
`db/migration/V2026_10_06__widen_mfa_secret.sql`.

- **MFA secrets encrypted at rest.** New `EncryptedStringConverter` (JPA `AttributeConverter`,
  reusing the `config.encryption.key` AES-256-GCM key) applied via `@Convert` on
  `User.mfaSecret` — deliberately *not* auto-applied, so only MFA secrets change. `ConfigEncryptionUtil`
  gained a static `getInstance()` because Hibernate instantiates converters itself and cannot
  dependency-inject. Column widened `varchar(64)` → `varchar(255)` to fit the Base64 IV+ciphertext
  (a 32-char Base32 secret becomes ≈80 chars) — hence the new migration. Decrypt failure returns the
  stored value as-is so pre-encryption plaintext rows keep working and are re-encrypted on next save.
- **Dev MFA bypass gated behind an explicit flag.** `verify()` now needs
  `app.security.mfa-dev-bypass` (yml, dev-only) *and* non-production, instead of "any non-production
  DB". Stops a database first seeded in dev from leaving "123456" armed in production.
- **Access-token lifetime is a config value.** `JwtUtil.generateAccessToken` reads
  `SystemConfigService.accessTokenExpiryMs()` with `jwt.access-expiry` as the fallback; new
  `ACCESS_TOKEN_EXPIRY_MINUTES` key (`seed=false`).
- **Refresh-token rotation made atomic.** `RefreshTokenRepository.markUsed` is a conditional UPDATE,
  so two concurrent refreshes cannot both mint a family; an unknown `jti` is now refused instead of
  being tolerated ("pre-store sessions, test helpers").
- **MFA guessing throttled.** `registerFailedMfaAttempt` reuses the password lockout counters
  (`LOGIN_MAX_ATTEMPTS`/`LOGIN_LOCK_MINUTES`) in `AuthServiceImpl` and `SuperAdminServiceImpl` —
  previously a 6-digit TOTP could be brute-forced without limit.
- **Password policy enforced on change/reset.** `AuthServiceImpl.changePassword` /
  `resetPasswordWithToken` validate via `PasswordPolicy.violation`, and a confirm mismatch became a
  `400 BusinessRuleException("Passwords do not match")` instead of a masked 401.
- **`GlobalExceptionHandler.handleBadCredentials` now surfaces `ex.getMessage()`** — this is the D6
  "fix" from `docs/e2e-report-2026-10-05.md`, though it was never logged as such and left the
  pre-authentication account-state checks revealing account existence (see 2026-10-07).
  `handleDataIntegrity` was also switched to `getMostSpecificCause()` + case-insensitive matching.
- **Super-Admin login** gained a lockout check; the dead `existsByUsernameAndUserType` guards were
  removed (the `countByUserType(SUPER_ADMIN) > 0` singleton check already covers them; the
  `...AndFirmId(null)` guards could never match).
- **`HeaderWrapper.getHeaders`** no longer appends the original value behind a custom one (which
  returned the injected header twice).
- Comment strip leftovers removed (Javadoc/JWT `.id()` ordering notes, `isProductionMode()` deleted).
- Plus an `application-dev.yml` `app.security.mfa-dev-bypass: true`.

### Collateral — the suite was left red and it was never noticed
1. `TotpUtil` requires the new yml flag, but the **test profile never set it**, so
   `FullLifecycleE2ETest` died at the SA MFA-setup step ("Invalid authenticator code").
2. `V2026_10_06__widen_mfa_secret.sql` was **never applied to the dev PostgreSQL**, so an encrypted
   secret (≈80 chars) could not fit `varchar(64)` — a live break of the MFA-setup path.

Both were found and fixed on 2026-10-07.
