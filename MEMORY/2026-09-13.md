# 2026-09-13

## Bug Fixes & Enhancements (6 bugs + feature analysis)

### Bug 1: GetAllFirms — added `isTrial` flag
- Created `FirmListResponse` DTO with `isTrial`, `trialDays`, `trialExpiresAt` fields
- Added `getAllFirms()` to `FirmService` interface and `FirmServiceImpl`
- Added `GET /api/v1/super-admin/firms` endpoint in `FirmAdminController`
- **Why:** SA needs to see which firms are trial vs permanent in the firm listing page

### Bug 2: Custom permissions missing from `/permissions/grouped`
- **Root cause:** `PermissionServiceImpl.upsert()` created permissions but never created `ModulePermission` junction rows. The grouped query reads from `ModulePermission`, so custom perms were invisible.
- Added `linkPermissionToModule()` in `PermissionServiceImpl.upsert()` — creates `ModulePermission` entry for custom permissions
- Fixed `PermissionServiceTest` — added missing `ModuleRepository` and `ModulePermissionRepository` mocks
- **Why:** Without the junction row, `findAllGroupedByModule()` had no link between custom permissions and their module

### Bug 3: NOTIFICATION_MANAGEMENT not in DataInitializer
- Added `"NOTIFICATION_MANAGEMENT"` module to `moduleDefs` array (displayOrder=17, icon=BellIcon, path=/notifications)
- Added role-permission matrix row: FULL for SA and FIRM_ADMIN, NO_ACCESS for others
- **Why:** Notification permissions (NOTIFICATION_MANAGEMENT:VIEW, CREATE, etc.) were never seeded

### Bug 4: Firm Admin can delete default cloned roles
- Added `isDefaultClonedRole()` check in `FirmRoleServiceImpl.deleteRole()` — blocks ADVOCATE, PARALEGAL, CLIENT codes
- These are cloned from system templates when a firm is created; only Super Admin should delete them
- **Why:** Cloned roles had `isSystem=false` so existing guard passed; added explicit role-code check

### Bug 5: departmentId in Add Employee
- **Confirmed not in backend code.** `CreateEmployeeRequest` and `UpdateEmployeeRequest` don't have `departmentId`. This is a frontend-only concern.

### Bug 6: MFA reset for Firm Admin
- Added `resetMfa(UUID userId, MfaResetRequest request)` to `UserManagementService` interface
- Implemented in `UserManagementServiceImpl` with firm-scoped validation (Firm Admin can only reset MFA for users in their firm)
- Added `POST /api/v1/modules/users/{userId}/reset-mfa` endpoint in `UserManagementController`
- **Why:** Only Super Admin could reset MFA; Firm Admin needs it for their employees/clients

### Password Reset (Super Admin + Firm Admin)
- **Firm Admin:** Already existed — `POST /api/v1/modules/users/{userId}/reset-password` (works for all firm users: advocates, clients, paralegals, custom roles)
- **Super Admin:** Added `POST /api/v1/super-admin/users/{userId}/reset-password` — can reset any user's password across all firms
- Added `resetPassword()` to `SuperAdminService` interface and `SuperAdminServiceImpl`
