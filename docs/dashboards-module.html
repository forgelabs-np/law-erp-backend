Base path: /api/v1  ·  Server port: 6969 (dev)  ·  Auth: Bearer JWT

Audience: backend developers, frontend developers

Scope: the new dashboard feature set — Case Dashboard, Case Assignments, Global Dashboard

1 · What Changed

This is the complete list of backend changes the frontend needs to know about. The new feature is the dashboard set — two dashboards plus the case-assignment endpoints that power the case dashboard's role filter. On top of that, one field was removed from employee CRUD and several bugs were fixed that change API behaviour.

2Case Assignments — POST/GET/DELETE /api/v1/firm/matters/{matterNumber}/assignmentsNew featureAssign/revoke team members; drives the advocate role filter
3Global Dashboard — GET /api/v1/modules/dashboardNew featureSite-wide cross-module stats; SUPER_ADMIN vs FIRM_ADMIN scoping

Honest scope check

The new feature work is items 1–3 (the two dashboards + case assignments). Items 4–7 are changes made in the same session that the frontend must also account for — item 4 is a field removal, items 5–7 change response values. There were no other API changes.

2 · Case Dashboard

GET/api/v1/firm/dashboard

Role-filtered case overview for a single firm. One call returns everything the dashboard screen needs.

ADVOCATE / PARALEGALOnly matters they are assigned to (via Case Assignments) + only their own events today

3 · Case Assignments

Assign employees (advocates, paralegals, juniors, supervisors) to matters. Multiple people can be assigned to one matter with different roles. These assignments are what the case dashboard's role filter uses — an ADVOCATE/PARALEGAL sees exactly the matters they are assigned to.

POST/api/v1/firm/matters/{matterNumber}/assignments

Assign an employee to a matter. The user must be a firm employee (FIRM_USER); CLIENT accounts are rejected.

curl -s -X POST "http://localhost:6969/api/v1/firm/matters/APX-MAT-2026-00001/assignments" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"data":{"userId":"<employee-uuid>","assignmentRole":"PRIMARY_ADVOCATE"}}'

assignmentRole enum:

ValueMeaning
PRIMARY_ADVOCATELead counsel on the matter
CO_ADVOCATESecondary counsel
PARALEGALParalegal support
JUNIORJunior associate
SUPERVISORSupervising partner
GET/api/v1/firm/matters/{matterNumber}/assignments

List everyone assigned to a matter.

curl -s "http://localhost:6969/api/v1/firm/matters/APX-MAT-2026-00001/assignments" \
  -H "Authorization: Bearer $TOKEN"
# data: [ { "id", "matterId", "matterNumber", "matterTitle",
#           "userId", "userName", "assignmentRole", "createdAt" } ]
DELETE/api/v1/firm/matters/{matterNumber}/assignments/{userId}

Revoke all assignments for that user on the matter.

curl -s -X DELETE "http://localhost:6969/api/v1/firm/matters/APX-MAT-2026-00001/assignments/<userId>" \
  -H "Authorization: Bearer $TOKEN"
Note: matter creation is unchanged — POST /api/v1/firm/matters (see the curl collection). Create the matter first, then assign its team.

5 · Department Removed From Employee CRUD

The employee create/update endpoints no longer accept a departmentId field, and the employee response no longer contains a department object. The whole Department feature was dead code and has been deleted.

Frontend: remove departmentId from any employee create/update form and drop the department column from employee tables. Sending departmentId today is ignored (the DTO no longer maps it); it will not error, but it does nothing.

6 · Frontend Integration Guide

6.1 Authentication flow (unchanged, but required)

Both dashboards need a JWT. Login returns a status that tells the UI what to do next:

POST /api/v1/auth/login
{ "data": { "lawFirmCode": "APEX-LAW", "username": "…", "password": "…" } }

Response status:
  SUCCESS                   -> store accessToken, go to app
  PASSWORD_CHANGE_REQUIRED  -> show change-password screen, use passwordChangeToken
  MFA_SETUP_REQUIRED        -> show QR code (mfaQrCodeUri), then POST /auth/mfa/setup/confirm
  MFA_REQUIRED              -> show 6-digit input, POST /auth/mfa/validate
  (all with mfaToken + totpCode)

6.2 Case dashboard screen — one API call

GET /api/v1/firm/dashboard   (Authorization: Bearer <token>)

Render the four sections directly from the response — the backend already applied the role filter, so the frontend does not filter anything:

  1. stats — summary cards: total / active / dormant / closed matters, today's events, stale count.
  2. todayEvents — today's hearings: time, court room, judge, attending advocate, case ref.
  3. casePositioning — per-matter rows: current court, stage, last hearing date/outcome, next event, days since last hearing, stale flag.
  4. staleCases — the subset of positioning where stale == true (90+ days).

6.3 Assigning a team (admin flow)

  1. Create the matter: POST /api/v1/firm/matters (existing endpoint, unchanged).
  2. Assign the team: POST /api/v1/firm/matters/{matterNumber}/assignments per employee + role.
  3. To show who's on a matter: GET /api/v1/firm/matters/{matterNumber}/assignments.
  4. To remove: DELETE /api/v1/firm/matters/{matterNumber}/assignments/{userId}.

6.4 Global dashboard screen (admin-only)

GET /api/v1/modules/dashboard   (Authorization: Bearer <token>)

Only FIRM_ADMIN and SUPER_ADMIN may call it. Show the five sections: userStats (user counts by role), firmStats (firms), caseStats (matters + today's events + stale), scraperStats (court scraper totals), recentActivity (last 10 audit entries).

6.5 Role-based UI rules

ScreenShow toHidden from
Case Dashboard + AssignmentsFIRM_ADMIN, ADVOCATE, PARALEGALSUPER_ADMIN, CLIENT
Global DashboardFIRM_ADMIN, SUPER_ADMINADVOCATE, PARALEGAL, CLIENT

6.6 What changed vs. the old frontend behaviour

  • FIRM_ADMIN dashboard is no longer empty. A bug meant the admin role was never detected, so admins saw only "assigned" matters (usually none). After the fix, FIRM_ADMIN sees all firm matters.
  • No more 500 on the dashboard. A matter without a court case or without any hearing used to crash the whole dashboard; now it renders with daysSinceLastHearing: null.
  • Employee forms: remove the department field.

7 · Full Curl Collection

Ready-to-run: docs/dashboards-curl-collection.sh (edit the CONFIG block at the top). Postman: docs/dashboard.postman_collection.json. The same commands are below for copy/paste.

Auth

BASE=http://localhost:6969

# 1. Login
curl -s -X POST "$BASE/api/v1/auth/login" -H "Content-Type: application/json" \
  -d '{"data":{"lawFirmCode":"APEX-LAW","username":"firmadmin","password":"pass"}}'

# 2. If PASSWORD_CHANGE_REQUIRED
curl -s -X POST "$BASE/api/v1/auth/change-password" -H "Content-Type: application/json" \
  -d '{"data":{"passwordChangeToken":"<pct>","newPassword":"NewPass123","confirmPassword":"NewPass123"}}'

# 3. If MFA_REQUIRED
curl -s -X POST "$BASE/api/v1/auth/mfa/validate" -H "Content-Type: application/json" \
  -d '{"data":{"mfaToken":"<mfaToken>","totpCode":"123456"}}'

TOKEN="<accessToken>"
AUTH="Authorization: Bearer $TOKEN"

Case Dashboard

# Role-filtered (FIRM_ADMIN = all, ADVOCATE/PARALEGAL = assigned only)
curl -s "$BASE/api/v1/firm/dashboard" -H "$AUTH"

# Create a matter (feeds the dashboard)
curl -s -X POST "$BASE/api/v1/firm/matters" -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"data":{"matterType":"LITIGATION","title":"Contract dispute - ACME vs Beta","originatingCourtLevel":"DISTRICT","courtName":"Kathmandu District Court","courtCaseNumber":"081-C1-7530","filingDate":"2083-04-29"}}'

# Assign an employee (PRIMARY_ADVOCATE)
curl -s -X POST "$BASE/api/v1/firm/matters/APX-MAT-2026-00001/assignments" \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"data":{"userId":"<employee-uuid>","assignmentRole":"PRIMARY_ADVOCATE"}}'

# List assignments
curl -s "$BASE/api/v1/firm/matters/APX-MAT-2026-00001/assignments" -H "$AUTH"

# Revoke assignment
curl -s -X DELETE "$BASE/api/v1/firm/matters/APX-MAT-2026-00001/assignments/<userId>" -H "$AUTH"

Global Dashboard

# FIRM_ADMIN = own firm | SUPER_ADMIN = all firms
curl -s "$BASE/api/v1/modules/dashboard" -H "$AUTH"

# Super admin login (separate endpoint, also MFA-gated)
curl -s -X POST "$BASE/api/v1/super-admin/login" -H "Content-Type: application/json" \
  -d '{"data":{"username":"superadmin","password":"pass"}}'
